A dedicated `/bw shout` command sends messages to everyone in the arena. Chat formatting is fully configurable and team-only chat is the default during matches, keeping team strategies private while allowing public calls when it matters. Together they close the two most abused gaps in BedWars servers: rage-quit escapes and command-based exploits.

### Per-Player Language Selection
All plugin messages are fully multi-language, and each player selects their own language individually. Messages, quest text and menu content resolve per player — not per server — making the plugin instantly usable for international communities.

## Why Exclusively 1.8.8?

Targeting a single version is a deliberate decision that guarantees stability and maximum speed.

## Reliability & Fair Play

Smooth performance means nothing without correct behavior in the moments that matter. BedWars ships an entire layer dedicated to the real-world situations live networks actually hit — most of it invisible until the day it saves your server.

### Players Never Join a Broken Server
At startup, connections are politely held until **every arena has finished loading**, with a built-in failsafe so a single broken map can never lock your lobby forever. Players never fall into a half-loaded world — and never even notice the process.

### Global Maintenance Mode
Live networks need a master switch, and BedWars ships one as a first-class add-on. `/bw maintenance on` (admin-only, from the lobby) stops every running arena, sends all players and spectators back to the lobby, closes practice sessions with a full inventory restore, and clears the ranked and invis-practice queues — then keeps every join path (arena, spectator, rejoin, practice and queue) blocked until you run `/bw maintenance off`. While the mode is active, everyone online sees a clear title and chat broadcast naming the administrator who pulled the switch, and a confirmation broadcast the moment systems return. Staff holding `bedwars.admin` bypass the block so your team can keep working inside arenas, and games created by the ranked Discord bot adapter are exempt — bot queueing keeps running throughout maintenance. Every title, subtitle, broadcast and sound is configurable in `Addons/Maintenance/config.yml`, and an existing Meeting-mode config from an older install migrates automatically.

### Queues That Cannot Corrupt Each Other
A player waiting in the practice queue cannot join, spectate or interfere with ranked games, and vice versa. Every rejection comes with a clear chat message. Competitive integrity is enforced by the game itself, not by an honor system.

### Respawn Chat Protection
While a player is respawning, their messages carry a grey `[RESPAWNING]` tag, are visible only to their own team, and shout commands are blocked entirely. Dead players can no longer relay enemy positions across the map.

### A Spectator Teleporter That Behaves
The teleporter is a clean, paginated menu of all alive players, with a dedicated random-teleport button. Players who are mid-respawn are always excluded, so spectators can never teleport into a death animation.

### Safe Eliminations and Rejoins
Eliminated players convert to spectators through a protected transition, so a game-end health reset can never accidentally kill someone a second later. Players who disconnect mid-match can rejoin and recover their exact inventory and position.

### Admin Tools With Guard Rails
Force-join commands validate the target arena before moving players and always report a clear error instead of failing silently. Disabling and re-enabling an arena is reliable and repeatable — no restart required, no hidden state left behind.

### Maps Stay Pristine Between Games
Every arena is restored from its pristine copy between matches, so game-time damage never accumulates across games. Map files, metadata and world settings are preserved untouched — your builds look identical on match one and match one thousand.

### Clean Failure Modes
Running the plugin on an unsupported server version is detected immediately and reported with a clear message — never a cryptic console error in the middle of your startup. Config-driven commands are validated before they run, producing one clean warning instead of console spam.

## Replay System

The replay system delivers studio-grade match recordings without any compromise on server performance. It is deeply integrated into the game itself — recording starts when the match starts and stops when it ends, with zero commands and zero configuration.

- **Automatic recording** – every match is captured, named and tagged with arena, mode and date.
- **Complete event capture** – movement, blocks, hits, kills, bed breaks and pickups, all recorded.

## Database & Storage

Data persistence is a first-class component of BedWars, not an afterthought.

- **Dual-engine architecture** – MongoDB and SQLite behind one unified interface; switching between them is a single config change.
- **Tuned out of the box** – connection pooling, write-ahead logging and busy-timeouts are pre-configured for maximum performance on both engines.
- **Batch economy saving** – token changes are accumulated and flushed in bulk, reducing write pressure dramatically on busy networks.
- **Asynchronous MongoDB** – even complex queries never touch the game thread.

- **Safe on failure** – failed writes are rolled back cleanly, and shutdowns close every connection gracefully. Your data survives crashes, restarts and migrations.

## Optional Integrations

PlaceholderAPI is the **only required dependency**. Beyond that, BedWars detects and enhances itself automatically when these plugins are present — and runs perfectly without them:

- **SlimeWorldManager** – unlocks in-memory, millisecond map resets. The replay add-on uses it for replay worlds and gracefully auto-disables itself when it is absent, so the rest of the plugin keeps running untouched.
- **Citizens** – enables join NPCs in your lobby and shopkeeper skin cosmetics.
- **Vault** – optional economy and chat hooks for networks that prefer an external economy. The built-in token economy remains fully functional without it.
- **Parties (AlessioDP)** – drop-in external party plugin support; the internal `/party` system needs nothing at all.
